# 冻结预测，验证后来有没有发生

## 先定义“爆”，再看结果

“爆款”至少含两个不同问题：一款游戏是否明显持续起量，以及是否达到很大规模。本版分别记，不能用小体量翻倍冒充平台级大爆款。

以下目标是本版工作定义，不是Roblox官方标准，也不是旧研究统计阈值的证明。

| 标签 | 本版定义 | 用途 |
|---|---|---|
| sustained_breakout_30d（主标签） | 冻结后30个完整UTC日内，至少连续3个合格日的日中位CCU ≥ max(10000, 3×冻结前最后完整日中位CCU) | 判断持续起量，不等于十万级规模 |
| scale_hit_30d | 同一窗口内，连续3个合格日日中位CCU≥100000 | 单独判断十万级持续规模 |
| peak_100k（诊断） | 同一窗口实际快照观察到CCU≥100000 | 区分一时活动峰和持续规模；未观察到不等于没发生 |

每个合格日≥18个不同小时桶，最长连续缺失≤4小时。小时内先中位聚合，避免密集抓活动导致偏差。

窗口从预测截止时间后的下一个UTC午夜开始，取30个完整日。不是偷换为“恰好到预测后720小时”；输出具体开始/结束时间。

无可靠基线时主标签阈值null，不造相对增长目标。规模标签仍能跟踪；预测票为ABSTAIN。用户可明确指定目标，但须在本次判断前冻结，并使用新版本，不能在结果出来后换标准。

## 预测文件

`evaluate.py score`的`scored.json`包括预测子对象：版本、游戏ID、data_as_of、基线、目标、采样规则、分数、覆盖、POSITIVE/NEGATIVE/ABSTAIN以及hash。文件采用不覆盖写入。

hash只能检测文件是否被改变，不是可信时间戳或抗恶意改写证明。有真实版本库时可在用户授权后提交文件作为时间记录，默认不自动commit/push。

本版POSITIVE仅对应HIGH_POTENTIAL；高覆盖且分<45为NEGATIVE；其余ABSTAIN。不是概率。不同目标不能合并一个“命中率”。

## 到7/14/30天怎样复查

复查是一次新的研究运行，需要外部调度或用户再次触发。Skill本身不常驻、不保证未来自动执行。7/14天先给中间状态，不把未达30天当失败。

读取原预测，合并同一Universe的后续真实快照，用新复查截止时间运行：

```bash
python "<SKILL_DIR>/scripts/evaluate.py" review "<ORIGINAL_RUN>/scored.json" "<HISTORY_JSONL>" --as-of "<REVIEW_UTC>" --out "<NEW_REVIEW_DIR>/review.json"
```

状态：
- `HIT`：已观察到连续3个合格日达到冻结门槛，可提前确认发生；统计完整30日队列指标时仍按到期队列处理。
- `NOT_HIT`：窗口到期，30天均有合格数据，仍没有达标序列。
- `PENDING`：窗口未结束且尚无已观察到的达标。
- `INCOMPLETE`：窗口结束但缺数据，不能把可能发生在缺口里的连续3天说成失败。
- `UNAVAILABLE`：没有冻结基线，无法检验主标签。

`peak_100k=NOT_OBSERVED`只表示没采到，不能当瞬时峰没有出现的证据。

冻结评分只使用当时已收集的数据。后来补的资料只能用于结果复查，不能静悄悄覆盖当时缺失项，再宣称预测准。

## 多游戏后，检验规则是否有用

完整保留入池候选，包括没选中的，不只复盘推荐成功案例。按Universe和冻结时间去重；同一游戏多次预测分组处理，不能当独立样本重复提高样本量。

队列按预测时点划分训练/调整与后续验证。旧60样本可用于提出假设，不能同时当独立测试集。2026样本与前两年分开报告，注意抽样和数据泄漏。

至少输出：

```text
eligible_matured_predictions
positive_predictions / negative_predictions / abstentions
observable_outcomes / incomplete_outcomes
TP / FP / FN / TN
precision = TP / (TP+FP)                  # 分母0 => null
recall_within_scored_cohort = TP/(TP+FN)  # 不是全Roblox召回率
abstention_rate
coverage_rate
precision_at_k for a frozen same-day ranked pool
lead_time_days = 首次达到冻结条件时点 - 预测时点
```

ABSTAIN里的后来命中另报“未决候选命中数”，不藏起来。只有持续跟踪非推荐/低分候选，才有机会发现漏检。小样本不要夸成功率；给分子分母和必要区间。

等有足够、按时间分离的真实前瞻结果再考虑概率校准。不能用手写逻辑函数把80分换成80%或90%。本版不自动训练、不在线改权重、不引入机器学习平台。

每次错判复盘只写：当时证据是什么、后来发生什么、是数据缺失/口径错/规则错/不可预知事件哪一类、下一版具体改哪条。不要用事后故事替代验证。
